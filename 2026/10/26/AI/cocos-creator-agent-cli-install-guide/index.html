从安装到接入：Cocos Creator Agent CLI 配置实录

  上一篇介绍了 Cocos Creator Agent CLI 的组成。这一篇直接走安装流程：准备 Node.js，安装 CLI，配置一个 AI Host，再把 CLI 项目扩展接入 Creator 工程。

  先说明范围：这里的 cocos-creator-agent 是 CocosAgent 项目提供的 Creator 2.x Agent CLI，不是 Cocos 官方 cocos 命令行工具。CLI 当前接受 Creator 2.4.1–2.4.16；项目现有实机验收证据主要来自 2.4.15。开始前仍要核对自己工程的精确 Creator 版本。

1. 准备环境并选择发布版本

3. 把项目扩展安装到目标工程

  CLI 可以只作为 Skills 和终端工具使用；要读写活动场景或调用 Creator 编辑器能力，还需要把扩展接到具体工程。先在 Cocos Dashboard 确认项目名称、绝对路径、Creator 版本和打开状态，再对准确的项目目录执行安装：

  安装命令会把扩展放进工程的 packages/ 目录。之后使用 CLI 打开目标工程，并检查扩展状态：

  打开后仍要在 Creator 窗口核对版本和工程路径。CLI 的 project open 会等待扩展握手与工程信息往返；只有编辑器端实际返回了匹配的工程身份，editorReady 才代表连接就绪。遇到超时，应先检查 Creator 是否正在加载、扩展是否启用，以及打开的路径是否正确。

  MCP 目录和直接 CLI 调用共用命令合同，但哪些工具可调用还受当前 Creator 实例、扩展版本和任务流程约束。文章第一篇解释了这些组件如何分工；下一篇会讲 Skill 路由与写入操作的核验边界。

常见问题

  • CLI 命令不存在：检查 Node.js 全局安装目录是否在 PATH 中，再运行 cocos-creator-agent version --format json。
  • Host 看不到工具：确认运行过 mcp configure，随后完整重启 Host，并检查 mcp status <client>。
  • Skill 没出现：确认 skill install 使用了目标 Host 名称，再查看 Host 的 Skill 目录或运行 skill show --list。
  • Creator 工程没有编辑器工具：检查扩展是否安装到正确工程、Creator 是否加载扩展、实例版本是否受支持，并查看 extension status 与 doctor 的具体输出。
  • 版本能选中但行为不符合预期：区分“版本被 CLI 接受”和“功能在该补丁版实机验收通过”。当前项目的实机证据不能自动外推到所有 2.4.x。

  完整命令、能力范围和最新发布信息以项目 README 为准。版本、Host 和工程路径最好写进自己的接入记录，排查问题时才知道当前连接的究竟是哪一个 CLI、Creator 和工程。
